# scaraSurrogate

2軸水平スカラアーム(平面2関節ロボットアーム)の物理モデルをNeural State Space (NSS)
モデルでサロゲート化し、ロールアウト誤差・制御タスクでの実用性を検証するプロジェクト。

姉妹プロジェクト [surrogateRolloutVerification](https://github.com/yk142/surrogateRolloutVerification)
(振り子)で得た教訓([LESSONS.md](https://github.com/yk142/surrogateRolloutVerification/blob/main/LESSONS.md)参照)
を踏まえて進める。特に「既知の物理構造をハードコードし、NNは残差のみを学習するグレーボックス化」
が、ロールアウト誤差にも制御タスクの実用性にも桁違いに効くことが分かっているため、本
プロジェクトでもこの知見を活用する。

## 対象系

**Phase 1(まずここから)**: 水平面内2関節アーム。関節はいずれも鉛直軸まわりの回転で、
アームは水平面内を動くため**重力は関節トルクに影響しない**。振り子になかった新しい難しさは
慣性結合(2つの関節の運動が力学的に結合する)とコリオリ/遠心力項。

**Phase 2(その後)**: 垂直面内2関節アーム。Phase 1に重力項が加わり、関節角度の組み合わせに
依存する非線形な重力トルクが生じる(単振り子の重力項の2自由度への拡張)。

## 力学モデル(Phase 1: 水平面、標準的な2リンクマニピュレータの運動方程式)

状態 `x = [θ1, θ2, θ̇1, θ̇2]`、入力 `u = [τ1, τ2]`。

```
M(q) q̈ + C(q, q̇) q̇ + F(q̇) = τ
```

- `M(q)`: 慣性行列(2x2、対角外項が関節間の慣性結合を表す)
- `C(q, q̇)`: コリオリ・遠心力項(2x2)
- `F(q̇)`: 摩擦(粘性、必要に応じてクーロン摩擦も追加)
- 重力項なし(水平面のため)

```
M11 = I1 + I2 + m1*lc1^2 + m2*(l1^2 + lc2^2 + 2*l1*lc2*cos(q2))
M12 = M21 = I2 + m2*(lc2^2 + l1*lc2*cos(q2))
M22 = I2 + m2*lc2^2

h = -m2*l1*lc2*sin(q2)
C11 = h*θ̇2,  C12 = h*(θ̇1+θ̇2)
C21 = -h*θ̇1,  C22 = 0
```

無トルク・無摩擦なら全運動エネルギー `0.5 * q̇ᵀ M(q) q̇` が保存される(水平面のため
位置エネルギーがない)ことが、シミュレータ正しさの基本的な検証になる。

## 力学モデル(Phase 2: 垂直面、重力あり)

Phase 1と同じ`M(q)`, `C(q,q̇)`(角度の取り方が同じなら同一の式)に加えて、
重力項`G(q)`が入る:

```
M(q) q̈ + C(q, q̇) q̇ + G(q) + F(q̇) = τ

G1 = (m1*lc1 + m2*l1)*g*cos(q1) + m2*lc2*g*cos(q1+q2)
G2 = m2*lc2*g*cos(q1+q2)
```

q1は水平(x軸正方向)を基準とした絶対角、q2はリンク1に対する相対角。無トルク・
無摩擦なら力学的全エネルギー(運動エネルギー+位置エネルギー)が保存されることが
検証になる。鉛直下向き(q1=-π/2, q2=0)は重力トルクが0になる不動点。

## マイルストーン

- **M1** (完了, #1): 水平2関節アームの真値シミュレータ(RK4)を実装し、運動エネルギー
  保存を検証する。
- **M2** (完了, #3): データセット生成、NSS(ブラックボックス/グレーボックス)モデル、
  マルチステップ損失+カリキュラム学習を実装。真の系には最初から粘性+クーロン摩擦を
  含め(姉妹プロジェクトM15相当を先取り)、同一学習レシピで比較した結果、
  **開ループロールアウトRMSEでグレーボックスが7〜9倍優位**(ゼロトルク条件:
  2.33→0.33、ランダムトルク条件: 2.97→0.48)。慣性結合・コリオリ項を持つ
  多自由度系でも姉妹プロジェクトの知見が再現された。以降のデフォルトモデルは
  `GrayBoxModel`。
- **M3** (完了, #5): 既知の慣性行列M(q)・コリオリ行列C(q,q̇)を使う計算トルク法で
  PTP(点対点)制御を実装し、真の物理モデル(オラクル)・グレーボックス・
  ブラックボックスの3条件を比較。ブラックボックスは全12ICで完全に破綻(0/12成功)。
  グレーボックスは全IC成功(12/12)し、真値(9/12)より成功率が高いという逆転が
  見られたが、これは学習された摩擦残差が真のクーロン摩擦のスティクション(静止時の
  粘着による定常誤差)を完全には再現できておらず、真値が陥る定常誤差をたまたま
  回避しているためと考えられる(振り子プロジェクトM5/M12の楽観バイアスと同種の現象)。
- **M4** (完了, #7): M3で見送っていた`INTEGRAL_CLIP`引き上げ(2.0→4.0)を実施し、
  真の物理モデルの摩擦固着を解消。全12ICで真値・グレーボックスとも成功(12/12)
  となり、誤差の水準もほぼ同オーダー(0.01〜0.05)に揃った。ブラックボックスは
  依然として全12ICで破綻(0/12)。
- **M5** (完了, #9): M4後のPTP代表試行で見られたグレーボックスのオーバーシュートの
  原因を診断。真値軌道上で残差ネットの摩擦予測を直接比較したところ、
  オーバーシュート区間限定の誤差悪化ではなく、角速度≈0付近で残差ネットが
  `sign(q_dot)`の不連続性を学習しきれずクーロン摩擦(0.02)を系統的に過小評価する
  定常バイアスが根本原因と判明。角速度は終始学習レンジ内のため分布外問題ではない。
- **M6** (完了, #11): M5の診断を踏まえ、残差ネットの入力に`tanh(q_dot/eps)`
  (sign(q_dot)の滑らかな近似)を明示的な特徴量として追加。静止付近の摩擦推定
  バイアスが縮小し(オーバーシュート区間RMS: joint1 0.021→0.013、joint2
  0.018→0.005)、副次効果として開ループロールアウトRMSEも大幅改善(ゼロトルク:
  0.33→0.14、ランダムトルク列: 0.48→0.14)。PTP制御は引き続き12/12成功を維持。
- **M7** (完了, #13): 最終誤差の到達判定だけでは検証できていなかった整定時間・
  過渡応答全体の一致度を新たに評価。12IC中10ICでグレーボックスが真値より
  大幅に速く整定し(過渡応答が楽観的すぎる)、最大オフセットの2ICでは逆に
  大幅に遅く整定するという、成功判定だけでは見えない不一致を発見。
- **M8** (完了, #15): M7で見つかった「速すぎる整定」に対応し、`FRICTION_SIGN_EPS`
  を0.05→0.01に縮小(PTP収束中の低速域でtanh特徴量がsign(q_dot)からより
  乖離しないように)。摩擦推定バイアスが更に縮小し(オーバーシュート区間RMS:
  joint1 0.013→0.008、joint2 0.005→0.001)、負オフセット側のICで整定時間の
  差が大幅縮小。ただし最大オフセットの外れ値ICは改善せず(むしろ悪化)、
  トルク飽和領域の問題は別要因として残る(#16で継続調査)。
- **M9** (完了, #17): M8の外れ値ICを診断した結果、トルク飽和の継続時間・
  解除タイミングは真値・グレーボックスで完全一致しており、当初の仮説
  (トルク飽和領域特有の問題)は否定された。真の原因は`FRICTION_SIGN_EPS=0.01`
  が近傍速度の微小変化に過敏で、残差ネットの摩擦予測がチャタリング(高周波
  振動)していること(スライディングモード制御のバウンダリレイヤー問題と同種)。
- **M10** (完了, #19): `FRICTION_SIGN_EPS`を0.03に再調整し、バイアス低減と
  チャタリング抑制のバランスを検証。eps=0.05/0.01/0.03の3点比較で、
  0.03が整定時間差の平均・最大の双方でバランスの良い妥協点と判明したが、
  最大オフセットの外れ値ICは依然として改善が乏しい。診断の結果、この
  ICでは真値自体にもjoint1の速度符号が微小反転する(スティックスリップ的な)
  挙動があり、滑らかな残差ネットでは原理的に再現しづらいことが分かった。
  既知の限界として記録し、これ以上のeps単独調整は打ち切る。
- **M11** (完了, #21): M9/M10の根本原因(sign(q_dot)という不連続関数をNNで
  近似する構造的な限界)に対応するため、グレーボックスのNN構造は維持したまま
  **真のモデル側の摩擦を`sign(q_dot)`から`tanh(q_dot/V_STRIBECK)`(Stribeck風の
  滑らかな摩擦モデル)に変更**。これにより不連続性そのものが消え、残差ネットが
  ほぼ完全に一致するようになった:
  - 真値-グレー間の過渡誤差ピーク: 0.16rad→**0.02rad**(12IC平均、M7比)
  - 摩擦推定誤差RMS(外れ値IC): joint1/joint2 0.0195/0.0180→**0.0026/0.0028**
  - 整定時間差: 平均7.63s→**3.54s**、最大19.1s→**13.2s**
  - 開ループロールアウトRMSE: 0.14→**0.11**
  - PTP最終誤差: 真値・グレーともに0.001〜0.013の範囲に収束(M8時点は0.02〜0.06)
  摩擦の滑らか化で真の系の実効的な静止摩擦(スティクション)が弱まり収束が
  遅くなったため、PID制御の積分ゲイン`KI`を0.3→0.8に再チューニングした。

### Phase 2(垂直面2関節アーム、重力あり)

- **Phase2-M1** (完了, #23): 重力あり垂直面2関節アームの真値シミュレータを
  `src/physics_vertical.py`に実装。Phase 1の`M(q)`, `C(q,q̇)`をそのまま再利用し、
  重力項`G(q)`を追加。無トルク・無摩擦での力学的全エネルギー保存(相対変動
  6.31e-04)、鉛直下向き(q1=-π/2, q2=0)が不動点であることを検証した。
- **Phase2-M2** (完了, #25): データセット生成・NSSモデル(ブラックボックス/
  グレーボックス)を実装。**Phase 1の摩擦係数(粘性0.05)をそのまま流用すると、
  重力+リンク2の小さい慣性によるカオス的な二重振り子効果でランダムIC・
  ランダムトルクの軌道がほぼ全て角速度数十rad/s(非現実的)まで発散する
  ことが判明**。実機ロボットアームの減速機・モータ由来の粘性摩擦を模して
  `C_VISCOUS`を0.05→2.0に引き上げ、現実的な速度域(数rad/s)に収めた
  (念のため角速度上限を超える軌道を棄却して引き直す安全弁も追加)。
  ブラックボックスは重力なしPhase 1と共通の`NSSModel`をそのまま再利用、
  グレーボックスは重力項`G(q)`をハードコードした`GrayBoxModelVertical`を新設。
  開ループロールアウトRMSEでグレーボックスが優位(ゼロトルク条件: 0.39→0.28、
  ランダムトルク条件: 0.43→0.20)だが、Phase 1(7〜9倍)ほどの差ではなく、
  重力+カオス性のある系ではグレーボックス化の恩恵がやや小さくなることが
  分かった。
- **Phase2-M3** (完了, #27): 重力補償項G(q)込みの計算トルク法PTP制御を
  `src/control_vertical.py`に実装。C_VISCOUS=2.0という大きな摩擦に対して
  Phase 1のゲイン(KP=6,KD=6)では収束が弱すぎ0/12ICしか成功しなかったため、
  ゲインを大幅に引き上げ(KP=30, KD=22, KI=3.5)て真の物理モデルは12/12
  成功を達成。しかし**グレーボックスは3/12しか成功せず**(ブラックボックスは
  0/12)、代表試行ではtheta2に真値にはない持続的な振動(減衰しないリミット
  サイクル的な挙動)が見られた。Phase2-M2で示唆した通り、重力+カオス性の
  ある系では、既知の物理構造を使っても残る摩擦推定誤差が閉ループ制御下で
  拡大しやすく、グレーボックス化だけでは実用レベルの制御精度に届かない
  ことが判明。追加調査は別Issueで継続する。
- **Phase2-M4** (完了, #29): PTP持続振動の原因を診断。グレーボックス自身の
  閉ループ軌道は減衰しないリミットサイクルを示し、その軌道上での摩擦推定を
  見るとjoint2で真値(振幅±0.5Nm)を大幅に下回る(±0.2Nm程度)過小評価が
  判明。C_VISCOUS=2.0(Phase1比40倍)という大きな係数を残差ネットが
  十分学習できていないことが根本原因と特定した。
- **Phase2-M5** (完了, #31): C_VISCOUSを2.0→1.0に緩和(データ生成の棄却
  サンプリングと併用し、角速度暴走は引き続き防止)。PTP成功数は3/12→5/12に
  改善したが、代表ICの持続振動は解消せず、摩擦推定誤差も同程度の大きさ
  (joint1/joint2 RMS: 0.26/0.27)のまま残った。C_VISCOUSをこれ以上下げると
  棄却サンプリングの採択率が急落し(0.7→23%, 0.5→8%)データ品質が悪化する
  ため、この軸だけでの追い込みは限界と判断。学習レシピ(データ量・エポック
  数・ネットワーク容量)の強化との組み合わせが次の課題として残る。
- **Phase2-M6** (完了, #33): データ量(600→1200)・ネットワーク容量
  (64,2層→128,3層)・エポック数を増強してみたが**逆効果**だった。学習ログで
  k=30(0.6秒先読み)ステージのロスが激しく振動し収束が不安定化、PTP成功数は
  M5の5/12から**0/12に悪化**した。カオス的な系では単純な容量・データ量の
  増加がかえって多段ロールアウト損失の学習を不安定化させることが判明。
  設定はM5の値(既定容量・データ量)に戻し、この方向性は打ち切った。
- **Phase2-M7** (打ち切り, #35): 残差ネットの出力をトルクから加速度に変更
  (M(q)^-1による勾配増幅の回避を狙う)を試したが、同一学習予算では収束
  自体が悪化し(k=30 train_loss: 0.004→1.3)、PTP成功数も5/12→0/12に
  悪化。マージせず知見のみ記録。
- **Phase2-M8** (完了, #37): 文献調査([Neural Robot Dynamics](https://arxiv.org/html/2508.15755v1)、
  DeLaN系のトルク分離手法等)を踏まえ、2つの変更を組み合わせた:
  (1) 学習損失をencode_stateの各成分の標準偏差で正規化(角速度成分の分散が
  角度成分の約28倍あり、素のMSEでは角度精度への実効的な重みが小さすぎた)、
  (2) 摩擦の残差ネット(自由なMLP)を廃し、`StructuredFrictionGrayBoxModelVertical`
  として摩擦の関数形(粘性+クーロン)自体をハードコードして係数のみ学習する
  設計に変更(M4で判明した「線形ゲインを学習しきれない」問題を構造的に解消)。
  結果、学習が全カリキュラム段階で滑らかに収束し(スパイクなし)、学習された
  粘性係数は真値(1.0)に対し0.96〜0.97とほぼ正確に一致。**PTP成功数は
  12/12を達成**し、代表ICの持続振動も完全に解消した。ロールアウトRMSEも
  ランダムトルク条件で23倍改善(0.80→0.034)。Phase 2でもグレーボックス化が
  実用レベルの制御精度に到達することを示せた。

## ディレクトリ構成

```
src/
  physics.py           # 2リンクマニピュレータの運動方程式(粘性+クーロン摩擦込み) + RK4シミュレータ
  dataset.py           # IC/トルクサンプリング・ロールアウト窓データセット生成
  model.py             # NSSModel(ブラックボックス) / GrayBoxModel(既知物理+残差、デフォルト)
  train.py             # 学習ループ(マルチステップ損失+カリキュラム学習)
  rollout.py           # 自己回帰ロールアウト + RMSE計算
  evaluate_graybox.py  # ブラックボックス vs グレーボックスの比較・プロット生成
  control.py           # 計算トルク法によるPTPコントローラ(積分項つき)
  evaluate_ptp.py      # PTP制御の3条件比較・プロット生成
  evaluate_transient.py    # 整定時間・過渡応答全体の比較評価
  diagnose_overshoot.py    # グレーボックスの摩擦推定誤差の診断
  diagnose_saturation.py   # 大オフセットIC(トルク飽和領域)の診断
  physics_vertical.py      # Phase2: 重力あり垂直面2関節アームの真値シミュレータ
  verify_physics_vertical.py  # Phase2: 物理シミュレータの検証プロット生成
  dataset_vertical.py      # Phase2: データセット生成(角速度上限による棄却サンプリング付き)
  model_vertical.py        # Phase2: GrayBoxModelVertical(慣性行列+コリオリ項+重力項+残差)
  train_vertical.py        # Phase2: 学習ループ
  evaluate_graybox_vertical.py  # Phase2: ブラックボックス vs グレーボックスの比較
  control_vertical.py      # Phase2: 重力補償込みの計算トルク法PTPコントローラ
  evaluate_ptp_vertical.py # Phase2: PTP制御の3条件比較・プロット生成
tests/
  test_physics.py
  test_model.py
  test_control.py
  test_evaluate_transient.py
  test_physics_vertical.py
  test_model_vertical.py
  test_control_vertical.py
```
